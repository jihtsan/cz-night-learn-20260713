# 课前必备知识：AI 编写 Excel 与生成 PPT

配套导图：[[AI办公课/02-课程思维导图-AI报表与PPT.canvas|查看课程思维导图]]

## 这节课真正要解决什么

学员不是只学“让 AI 做一个表格”，而是要完成一条完整的工作链路：

```mermaid
flowchart LR
    A[模糊想法] --> B[清晰需求]
    B --> C[结构化表格]
    C --> D[准确数据]
    D --> E[可解释结论]
    E --> F[可汇报 PPT]
```

完成本节课后，学员应该能：

- 向 AI 说明报表的目的、使用者和交付要求；
- 把零散想法整理成字段、指标、维度和筛选条件；
- 使用结构化提示词，让 AI 先澄清、再生成、最后自检；
- 看懂并使用 Markdown，必要时用 HTML 补充展示效果；
- 让 AI 协助设计报表、填写数据、生成公式或操作步骤；
- 检查表格是否存在空值、重复、格式混乱和计算错误；
- 从报表中提炼结论，并组织成一份结构清晰的 PPT。

> [!important] 核心认知
> AI 擅长整理、生成和解释，人负责提供业务背景、确认数据来源、检查结果并承担最终判断。

## 上课前需要懂的 7 件事

### 1. 把 AI 当作协作者，而不是许愿机

AI 不会自动知道公司背景、数据口径和领导关注点。输入越模糊，输出越容易“看起来完整，实际上不能用”。

学员需要建立三个基本认知：

- **AI 没有读心术**：没有提供的背景，它只能猜；
- **第一次回答只是初稿**：可以追问、修改和分阶段完成；
- **人负责最终判断**：关键数字、公式、结论和敏感信息必须人工确认。

> [!important] 一句话原则
> 不要只对 AI 说“帮我做一个报表”，要告诉它为什么做、给谁看、使用什么数据、怎样才算完成。

### 2. 学会写结构化提示词

配套讲义：[[AI办公课/03-为什么大模型需要提示词|为什么大模型需要提示词]]

提示词不是一句“神奇口令”，而是一份给 AI 的工作说明书。推荐使用下面的六段式结构。

| 模块 | 要说明什么 | 示例 |
|---|---|---|
| 角色 | 希望 AI 以什么身份思考 | 你是一名销售数据分析师 |
| 背景 | 为什么做、给谁看 | 为区域经理准备月度经营汇报 |
| 任务 | 具体需要完成什么 | 整理需求、设计报表、提炼结论 |
| 材料 | AI 可以使用哪些数据 | 订单明细、目标表、字段说明 |
| 输出 | 用什么格式和结构交付 | 先用 Markdown 给方案，再生成 Excel 和 PPT |
| 约束与检查 | 哪些不能做、怎样验收 | 不猜测缺失数据，列出公式和待确认项 |

#### 一个可复用的完整模板

```text
角色：你是一名【角色】。

背景：我要为【使用对象】完成【业务场景】，目的是【业务目标】。

任务：请完成以下工作：
1. 【任务一】
2. 【任务二】
3. 【任务三】

材料：我会提供【文件、文字、数据或参考样例】。只能基于已提供的信息工作。

输出：先使用 Markdown 输出【需求清单/字段表/处理步骤/页面大纲】，经我确认后，再生成【Excel/HTML/PPT】。

约束：
- 不要编造缺失数据；
- 发现信息不足时先提问；
- 保留原始数据，不直接覆盖；
- 标记使用的公式、口径和假设；
- 完成后给出检查结果与待人工确认项。
```

#### 模糊提示词与清晰提示词对比

**模糊版本：**

> 帮我做一个销售报表和 PPT。

**清晰版本：**

> 你是一名销售数据分析师。请为区域经理制作 6 月门店销售汇报，目标是判断哪些门店需要重点关注。我会提供订单明细和门店目标表。请先用 Markdown 整理字段、指标、计算口径和缺失信息，不清楚的地方最多提出 5 个关键问题。经我确认后，再设计报表结构，计算销售额、利润率和目标完成率，最后输出 5 页以内的 PPT 大纲。不得编造数据，所有结论要注明数据依据。

清晰版本多提供了：对象、目的、材料、步骤、指标、输出格式和验收规则。

#### 提示词最值得详细讲的 6 个技巧

1. **先说目的，再说动作**：先解释为什么做，AI 才能判断重点；
2. **把大任务拆成步骤**：需求、结构、样例、完整生成、检查、汇报依次完成；
3. **指定输出格式**：例如 Markdown 表格、字段清单、HTML 页面或 PPT 大纲；
4. **给参考样例**：告诉 AI“参考结构，不要照抄内容”；
5. **要求先提问**：信息不足时先澄清，不要立即生成；
6. **写清验收标准**：说明页数、字段、指标、计算口径和禁止事项。

> [!tip] 提示词不必一次写完
> 新手更适合“先写一版—让 AI 追问—补充信息—确认结构—再生成”的多轮协作方式。

### 3. 学会用多轮对话控制过程

不要让 AI 一次完成所有工作。推荐采用“六步对话法”：

```mermaid
flowchart LR
    A[说明目标] --> B[让 AI 提问]
    B --> C[确认需求]
    C --> D[先看 Markdown 方案]
    D --> E[生成文件]
    E --> F[检查与修改]
```

每一步可以这样说：

1. **澄清**：“先不要生成文件，请指出需求中不完整或矛盾的地方。”
2. **复述**：“请用清单复述你理解的目标、数据范围和交付物。”
3. **规划**：“请先用 Markdown 给出工作表结构、字段和计算口径。”
4. **试做**：“先处理 10 行样例，说明每一步做了什么。”
5. **生成**：“确认无误后，再处理完整数据并生成文件。”
6. **自检**：“请检查空值、重复、异常、公式和结论，并列出待人工确认项。”

### 4. 用业务语言整理需求

Excel 操作本身不作为本课的前置门槛，但学员仍要会描述报表需求。

至少说清楚：

- 为什么做：要解决什么业务问题；
- 给谁看：自己、同事、主管还是客户；
- 数据范围：时间、对象、数据来源；
- 看什么：需要哪些字段和指标；
- 怎么看：按哪些维度分析、使用哪些筛选条件；
- 怎么交付：明细、汇总、图表、HTML 页面还是 PPT；
- 什么时候要：截止时间和更新频率。

| 概念 | 它回答的问题 | 示例 |
|---|---|---|
| 字段 | 需要记录什么 | 日期、客户、地区、产品、金额 |
| 维度 | 按什么角度拆分观察 | 按月份、地区、产品类别 |
| 指标 | 计算或比较什么结果 | 销售额、订单数、利润率、完成率 |
| 筛选条件 | 只看哪些数据 | 今年、华东区、已完成订单 |

一句话判断：**“按什么看”通常是维度，“看多少、好不好”通常是指标。**

### 5. 认识 Markdown、HTML 和 DTD

后续课程建议采用：**Markdown 为主，HTML 为辅，DTD 只讲概念。**

| 格式 | 用途 | 本课定位 |
|---|---|---|
| Markdown | 快速表达标题、清单、表格、代码和页面大纲 | 主要沟通与中间交付格式 |
| HTML | 制作可在浏览器展示、可精细排版的页面 | 需要更强展示效果时使用 |
| DTD | 描述 XML 文档允许出现的结构和规则 | 了解“文档结构约束”概念即可 |

#### 为什么以 Markdown 为主

Markdown 接近自然书写，符号少，适合人与 AI 共同编辑。课程中可以用它来输出：

- 需求清单；
- 字段与指标表；
- 数据处理步骤；
- 检查清单；
- PPT 页面大纲；
- 需要人工确认的问题。

常用语法只需掌握这些：

```markdown
# 一级标题
## 二级标题

- 无序清单
1. 有序步骤
- [ ] 待办事项

| 字段 | 含义 |
|---|---|
| 销售额 | 订单含税金额 |

**重点文字**
```

#### HTML 什么时候使用

当 Markdown 的排版能力不够，或者需要浏览器页面、卡片、颜色、按钮和复杂布局时，可以让 AI 生成 HTML。

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8">
    <title>月度销售汇报</title>
  </head>
  <body>
    <h1>月度销售汇报</h1>
    <p>本月销售额同比增长 12%。</p>
  </body>
</html>
```

新手不需要背标签，可以先看懂结构，再让 AI 修改。需要注意：HTML 能控制页面展示，但它本身不等于 Excel，也不等于 PPT。

#### DTD 需要讲到什么程度

DTD 的全称是 **Document Type Definition**，主要用于定义 XML 文档中可以有哪些元素、元素如何嵌套以及出现顺序。

```dtd
<!ELEMENT report (title, summary)>
<!ELEMENT title (#PCDATA)>
<!ELEMENT summary (#PCDATA)>
```

这段规则表达的是：`report` 中应依次包含 `title` 和 `summary`。

> [!note] `<!doctype html>` 与 DTD 的区别
> 现代 HTML 文件开头常见的 `<!doctype html>` 是文档类型声明，用于告诉浏览器按现代 HTML 标准解析页面；它不是要求学员编写一套传统 DTD。课堂中认识它即可。

### 6. 知道怎样检查 AI 的结果

生成完成不等于工作完成。至少检查：

- **完整性**：必填信息是否缺失；
- **一致性**：名称、日期、单位和口径是否统一；
- **合理性**：数字和日期是否存在明显异常；
- **计算性**：总计、比例和公式是否正确；
- **可追溯性**：关键数字和结论能否找到来源；
- **格式性**：Markdown、HTML、Excel 和 PPT 是否能正常打开与阅读；
- **抽样核对**：随机选择部分数据，手工复算并对照原始资料。

建议要求 AI 同时说明：它做了什么、采用了什么规则、哪里不确定、需要人工检查什么。

### 7. 理解汇报逻辑与数据安全

报表负责保存数据、计算和分析；PPT 负责传达重点、解释原因和推动行动。从报表到 PPT 时，要依次回答：

1. **发生了什么？**
2. **为什么发生？**
3. **意味着什么？**
4. **接下来做什么？**

> [!tip] 一页一个结论
> PPT 页标题尽量直接写结论，例如“华东区贡献了本月 60% 的增长”，不要只写“区域分析”。

同时，在把资料交给 AI 前，要确认是否包含个人信息、客户名单、合同金额或财务数据；不确定时先脱敏，或者使用课堂模拟数据。

## 不需要提前掌握的内容

为了降低门槛，以下内容不应作为本节课的前置要求：

- 编程或 VBA；
- 复杂函数、宏和数据透视表高级功能；
- 专业统计学；
- 专业视觉设计；
- 系统学习 HTML 或编写 DTD；
- 一次写出“完美提示词”。

课堂上可以通过模板、示例和多轮对话逐步完成任务。

## 课前 15 分钟自检

- [ ] 我能说出任务给谁使用、要解决什么问题；
- [ ] 我能用角色、背景、任务、材料、输出和约束组织提示词；
- [ ] 我知道信息不足时应让 AI 先提问，而不是直接生成；
- [ ] 我能区分“按地区看”和“销售额”分别是维度与指标；
- [ ] 我能看懂 Markdown 的标题、清单和表格；
- [ ] 我知道 Markdown、HTML 和 DTD 的用途不同；
- [ ] 我知道 AI 生成的数字、公式和结论必须复核；
- [ ] 我不会把敏感数据直接提交给未经确认的 AI 工具。

如果有 6 项及以上可以勾选，就能顺利进入实操；不足的部分可以在正式实操前快速讲解。

## 建议的课前微课安排（20～30 分钟）

| 时间 | 内容 | 学员产出 |
|---|---|---|
| 5 分钟 | AI 能做什么、不能做什么 | 列出 3 项人工责任 |
| 10 分钟 | 六段式提示词与多轮对话 | 写出并改进一版任务提示词 |
| 5 分钟 | 字段、维度、指标、筛选条件 | 完成一张需求卡 |
| 5 分钟 | Markdown、HTML 与 DTD | 用 Markdown 输出需求清单 |
| 5 分钟 | 结果校验、汇报逻辑与隐私 | 完成检查清单并写出一页结论标题 |

## 实操前的需求卡

复制并填写下面内容，再交给 AI：

```text
报表名称：
业务目标：
使用对象：
数据来源：
统计范围：
每一行代表：
需要的字段：
需要的指标：
分析维度：
筛选条件：
更新频率：
Excel 交付要求：
PPT 交付要求：
敏感信息及处理方式：
截止时间：
```

## 课堂示例任务

> [!example] 示例：门店月度销售汇报
> 为区域经理制作 6 月门店销售报表。原始数据包含订单日期、门店、城市、产品类别、数量、销售额和成本。需要计算各门店销售额、利润额、利润率及目标完成率，找出表现最好和需要关注的门店，最后生成一份 5 页以内的月度汇报 PPT。

可以引导学员先让 AI 提问，再逐步完成：

1. 补全需求；
2. 设计 Excel 工作表与字段；
3. 填入或导入数据；
4. 生成公式与汇总；
5. 检查异常与计算结果；
6. 提炼 3 个核心结论；
7. 生成 PPT 大纲、页面标题和图表建议；
8. 人工复核后导出最终文件。

## 给培训师的教学提醒

> [!note] 先示范思考，再示范点击
> 对新手而言，最大的难点通常不是按钮位置，而是把业务问题翻译成表格结构。演示时应把“为什么这样问、为什么这样分列、为什么选择这张图”说出来。

- 先用 10～20 行模拟数据，避免一开始就处理复杂真实文件；
- 故意准备一份有空值、重复、日期混乱和单位不一致的数据，让学员练习发现问题；
- 先让学员口头描述需求，再填写需求卡，最后交给 AI；
- 每完成一步都保留中间结果，方便回退和对比；
- 评价标准优先看“需求是否清楚、数据是否正确、结论是否可信”，其次才是美观程度。
