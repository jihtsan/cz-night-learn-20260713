# 为什么大模型需要提示词

## 本节课的位置

这一节建议放在“需求商讨”之前。学员先理解为什么要向 AI 说清楚任务，后面再学习如何整理需求、生成报表和制作 PPT。

```mermaid
flowchart LR
    A[理解为什么需要提示词] --> B[学习提示词结构]
    B --> C[商讨业务需求]
    C --> D[生成报表与 PPT]
```

## 学习目标

完成本节后，学员应该能够：

- 解释大模型为什么需要提示词；
- 说出提示词能够带来的主要好处；
- 区分模糊提示词与具体提示词；
- 使用六段式结构写出一份基础提示词；
- 知道好提示词可以提高命中率，但不能代替人工检查。

## 一、为什么大模型需要提示词

大模型学习了大量知识，也能生成多种类型的内容，但它不会自动知道：

- 你真正想解决什么问题；
- 内容是给自己、同事、主管还是客户使用；
- 哪些信息最重要；
- 应该输出 Markdown、HTML、Excel 还是 PPT；
- 哪些内容可以合理推断，哪些内容绝对不能猜；
- 什么样的结果才算完成。

> [!important] 核心定义
> 提示词不是唤醒 AI 的“神奇口令”，而是人给 AI 的一份工作说明书。

同样一份材料，可以有很多种处理方向。例如，一份销售数据既可以用来检查异常，也可以用来评价门店、预测趋势或制作管理汇报。如果没有提示词，大模型只能根据有限的信息猜测用户想走哪条路线。

## 二、大海与游泳者的比喻

> [!example] 大海比喻
> 大模型就像一片巨大的海洋，里面包含大量知识、表达方式和解决问题的可能性。AI 的回答像一名正在海里游泳的人，提示词则是我们给他的目的地、方向、路线和安全要求。

如果我们只说：

> 你游过去吧。

游泳者会遇到很多问题：

- 从哪里出发？
- 要游到哪里？
- 应该走哪条路线？
- 需要多快到达？
- 中途需要避开什么？
- 到达后需要带回什么？

这就像只对 AI 说：

> 帮我做一个 PPT。

AI 虽然可以立即开始工作，但它只能猜测汇报对象、业务目标、页面数量和内容重点。最后可能得到一份“看起来像 PPT”的内容，却不一定能够解决真正的问题。

如果把指令改成：

> 请从东侧码头出发，游到前方的红色灯塔。避开左侧礁石区，全程控制在 30 分钟以内。到达后记录路线和水温，并用表格汇报。

游泳者就知道了出发点、目的地、路线、限制条件和最终交付物。

### 比喻与提示词的对应关系

| 大海中的要素 | 提示词中的含义 |
|---|---|
| 出发位置 | 当前背景和已有材料 |
| 目的地 | 最终目标 |
| 游泳者的身份 | AI 需要扮演的角色 |
| 游泳路线 | 任务步骤和处理顺序 |
| 礁石和危险区域 | 限制条件与禁止事项 |
| 到达时间 | 截止时间和效率要求 |
| 带回来的东西 | 输出格式和交付物 |
| 确认是否到达 | 验收标准和检查要求 |

> [!note] 比喻的边界
> 大模型并不是在数据库或知识海洋中简单“搜索答案”。它会根据当前上下文预测和生成内容。这个比喻主要帮助新手理解：可能方向很多，所以需要明确引导。

## 三、有提示词有什么好处

### 1. 帮助 AI 理解目标

AI 不只是知道“要做什么动作”，还知道“为什么要做”。这样才能判断什么内容应该重点呈现。

### 2. 减少猜测

背景越充分，AI 越不需要自行补充不存在的信息，也越容易主动发现缺失条件。

### 3. 聚焦重点

提示词可以明确要求关注哪些数据、指标、结论和使用对象，避免生成大量无关内容。

### 4. 控制工作过程

可以要求 AI 按照以下顺序工作：

```mermaid
flowchart LR
    A[先提问] --> B[确认需求]
    B --> C[输出方案]
    C --> D[生成文件]
    D --> E[自检和修改]
```

### 5. 控制输出格式

可以明确要求 AI 输出 Markdown 需求清单、HTML 页面、Excel 报表或 PPT 大纲。

### 6. 提高结果稳定性

同类任务使用相同的提示词结构，更容易获得结构一致、便于复用的结果。

### 7. 减少返工

开始前把目标、格式和验收标准讲清楚，可以减少后期反复修改。

### 8. 降低错误风险

提示词可以明确要求“不编造数据”“注明来源”“列出假设”“生成后自检”。

> [!warning] 提示词不是正确性保证
> 具体提示词能够提高结果的命中率和稳定性，但不能保证所有数字、公式和结论都正确。最终结果仍需要人工复核。

## 四、为什么提示词要具体

“有提示词”和“有具体提示词”并不完全相同。

### 模糊版本

> 根据这些销售数据做一份 PPT。

这个版本没有说明：

- 给谁看；
- 为什么做；
- 需要分析哪些指标；
- 需要多少页；
- 先做方案还是直接生成；
- 数据缺失时如何处理；
- 最终怎样验收。

### 具体版本

> 你是一名经营数据分析顾问。请根据我提供的 6 月门店销售数据，为区域经理设计一份月度经营汇报，目的是找出表现优秀的门店和需要重点关注的问题。请分析销售额、利润率和目标完成率。先不要直接生成 PPT，请先使用 Markdown 输出一份不超过 5 页的页面方案，包含页码、页面标题、核心结论、数据依据和建议图表。不得编造缺失数据，所有结论必须能追溯到原始数据。信息不足时，先向我提出不超过 5 个关键问题。

### 具体版本解决了什么

| 提示词内容 | 带来的好处 |
|---|---|
| 经营数据分析顾问 | 确定分析视角 |
| 区域经理 | 确定使用对象 |
| 找出优秀门店和问题 | 确定业务目标 |
| 销售额、利润率、完成率 | 确定分析指标 |
| 先输出 Markdown 方案 | 控制工作顺序 |
| 不超过 5 页 | 控制交付规模 |
| 结论注明数据依据 | 提高可追溯性 |
| 信息不足先提问 | 减少错误猜测 |

## 五、六段式提示词结构

初学者可以把提示词固定为六个模块：

| 模块 | 要回答的问题 |
|---|---|
| 角色 | 希望 AI 以什么身份思考？ |
| 背景 | 为什么做、给谁使用？ |
| 任务 | 具体需要完成哪些工作？ |
| 材料 | AI 可以使用哪些资料？ |
| 输出 | 使用什么格式和结构交付？ |
| 约束与检查 | 哪些不能做、怎样才算完成？ |

### 可直接使用的模板

```text
角色：你是一名【角色】。

背景：我要为【使用对象】完成【业务场景】，目的是【业务目标】。

任务：请完成以下工作：
1. 【任务一】
2. 【任务二】
3. 【任务三】

材料：我会提供【文件、文字、数据或参考样例】。只能基于已提供的信息工作。

输出：请先使用 Markdown 输出【需求清单/处理步骤/PPT 大纲】，经我确认后，再生成【Excel/HTML/PPT】。

约束与检查：
- 不要编造缺失数据；
- 发现信息不足时先提问；
- 标记使用的公式、口径和假设；
- 所有关键结论注明数据依据；
- 完成后列出检查结果和待人工确认项。
```

## 提示词之外：Skill 与项目规则

提示词只负责说明当前任务。面对需要反复执行的专业工作，Codex 还会使用：

- **Skill**：某一类任务的可复用工作流程。Codex 先看到 Skill 的名称、描述和路径；任务匹配后，再读取完整 `SKILL.md`；
- **`AGENTS.md`**：项目长期规则。Codex 开始工作前会自动加载适用的项目说明，例如文件路径、命名规范和验收要求；
- **Tool**：真正执行读取、写入、生成和检查的工具。

从整体上看，AI 当前用于工作的上下文还可能包括：

1. 系统与安全规则；
2. `AGENTS.md` 项目规则；
3. 可用 Skill 的名称、描述和路径；
4. 当前会话中的历史对话；
5. 长对话经过压缩后形成的摘要；
6. 已启用并与任务相关的跨会话记忆；
7. 当前用户提示词；
8. 被选中的完整 `SKILL.md`；
9. 上传或读取的文件；
10. 执行过程中产生的工具结果。

> [!note] 用户输入不是全部上下文
> 平常所说的“提示词”只是其中一层。AI 的实际工作依据，是由当前任务、项目规则、会话信息、专业流程和事实材料共同组成的动态上下文包。

## 六、建议的课堂讲解流程

| 时间 | 讲解内容 | 教学动作 |
|---|---|---|
| 2 分钟 | 为什么需要提示词 | 先问学员“帮我做 PPT”还缺少什么 |
| 3 分钟 | 大海与游泳者比喻 | 展示模糊指令与具体指令 |
| 3 分钟 | 提示词的主要好处 | 结合实际办公任务逐项说明 |
| 4 分钟 | 六段式提示词 | 拆解具体提示词中的六个模块 |
| 3 分钟 | 改写练习与点评 | 学员改写模糊提示词 |

## 七、课堂练习

### 练习题

请把下面的模糊提示词改写成完整提示词：

> 帮我根据销售数据做一个 PPT。

### 学员至少需要补充

- [ ] AI 扮演的角色；
- [ ] 汇报对象；
- [ ] 业务目标；
- [ ] 数据来源与范围；
- [ ] 分析指标；
- [ ] 工作步骤；
- [ ] 输出格式；
- [ ] 页数或篇幅；
- [ ] 数据与结论检查要求。

### 点评标准

不要只评价提示词“写得长不长”，重点看：

1. AI 是否知道目的地；
2. AI 是否知道应该怎样走；
3. AI 是否知道哪些地方不能去；
4. AI 是否知道最后交付什么；
5. 人是否能够检查它有没有完成。

## 八、讲师收尾话术

> [!quote] 三句话总结
> 大模型拥有广阔的知识，但不知道你的目的地。
>
> 提示词负责告诉 AI：从哪里出发、到哪里去、怎么走、最后交付什么。
>
> 好提示词可以提高结果的命中率，但不能代替人的检查与判断。
