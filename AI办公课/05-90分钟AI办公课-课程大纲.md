# 90 分钟 AI 办公课：从需求商讨到 Excel 与 PPT

配套导图：[[AI办公课/06-90分钟AI办公课-课程思维导图.canvas|打开 90 分钟课程思维导图]]

## 一、课程定位

这不是一节传统的 Excel 操作课，也不是一节只讲提示词的理论课。课程要带学员完成一条最小但完整的 AI 办公工作链：

```mermaid
flowchart LR
    A[理解 AI 怎样接收任务] --> B[用提示词商讨需求]
    B --> C[用 Markdown 固化方案]
    C --> D[生成并校验 Excel]
    D --> E[提炼结论]
    E --> F[设计并生成 PPT]
```

> [!important] 最终目标
> 学员要知道怎样把一个模糊的办公任务交给 AI，并通过“先商讨、再生成、后校验”的流程得到可以继续使用的 Excel 和 PPT，而不是只会说“帮我做一个文件”。

## 二、学员最终带走的 4 个产物

1. 一份结构完整的提示词；
2. 一份 Markdown 需求确认单；
3. 一份经过基础校验的 Excel 报表；
4. 一份 5 页以内的 PPT 方案或初稿。

## 三、课程深度分级

90 分钟时间有限，所有内容不能平均用力。建议按照下面三个层级控制深度。

| 深度 | 教学要求 | 本课程内容 |
|---|---|---|
| A｜必须会做 | 学员要实际完成一次 | 六段式提示词、需求商讨、Markdown 需求卡、结果校验 |
| B｜理解并会使用 | 学员能解释概念，知道什么时候使用 | 上下文、Skill、`AGENTS.md`、报表生成、PPT 叙事 |
| C｜知道即可 | 只建立概念，不展开技术细节 | HTML 视觉预览、DTD、Skill 开发、脚本和运行环境配置 |

> [!warning] 不要讲得太深
> Skill 只讲“先看名称与描述、匹配后读完整说明、按流程执行”；`AGENTS.md` 只讲“项目长期规则”；HTML 只演示用途；DTD 最多用一句话说明文档结构约束。不要在 90 分钟课堂中讲 Skill 开发、代码或系统配置。

## 四、90 分钟总时间表

| 时间 | 课程模块 | 核心问题 | 学员产出 | 深度 |
|---|---|---|---|---|
| 0～5 分钟 | 1. 开场与成果预览 | 今天最终能完成什么？ | 理解课程路线 | B |
| 5～25 分钟 | 2. AI、提示词与工作上下文 | AI 为什么需要清晰指令？ | 一份六段式提示词 | A/B |
| 25～40 分钟 | 3. 需求商讨与 Markdown 固化 | 生成前需要确认什么？ | Markdown 需求卡 | A |
| 40～60 分钟 | 4. 从数据到 Excel 报表 | AI 如何把需求变成可信报表？ | Excel 报表与检查结果 | A/B |
| 60～75 分钟 | 5. 从 Excel 到 PPT 方案 | 数据怎样变成汇报故事？ | 5 页 Markdown PPT 方案 | A/B |
| 75～85 分钟 | 6. 生成并检查 PPT | 怎样判断 PPT 能不能交付？ | PPT 初稿与检查清单 | B |
| 85～90 分钟 | 7. 复盘与迁移 | 下次怎样独立完成？ | 一张完整流程卡 | A |

总计：**90 分钟**。

## 五、逐块教学设计

### 第 1 块：开场与成果预览（0～5 分钟）

#### 教学目标

让学员先看到最终产物，理解这节课不是学习零散按钮，而是学习一条完整工作流程。

#### 分钟安排

| 时间 | 内容 |
|---|---|
| 0～2 分钟 | 展示原始数据、需求 Markdown、Excel 报表和 PPT 成品 |
| 2～4 分钟 | 介绍完整路线：需求 → Markdown → Excel → 结论 → PPT |
| 4～5 分钟 | 说明课堂边界与最终产出 |

#### 必须讲清楚

- Excel 是数据和计算载体，不是课程起点；
- PPT 是表达结论的交付物，不是把 Excel 直接复制过去；
- 真正起点是“这次任务要解决什么问题”。

#### 细化程度

- 展示成品即可，不讲 Excel 功能；
- 不讲模型技术原理；
- 不超过 5 分钟。

### 第 2 块：AI、提示词与工作上下文（5～25 分钟）

#### 教学目标

让学员明白为什么 AI 需要提示词，并认识 AI 完成任务时还会参考当前对话、Skill、`AGENTS.md`、文件和工具结果。

#### 分钟安排

| 时间 | 内容 |
|---|---|
| 5～8 分钟 | “大海与游泳者”比喻：为什么需要目的地和路线 |
| 8～14 分钟 | 六段式提示词：角色、背景、任务、材料、输出、约束与检查 |
| 14～18 分钟 | 动态上下文包：当前对话、摘要或记忆、项目规则、文件材料 |
| 18～22 分钟 | Skill 与 `AGENTS.md`：岗位 SOP 与项目员工手册 |
| 22～25 分钟 | 改写练习：“帮我做一个销售 PPT” |

#### 必须讲清楚

1. 提示词不是神奇口令，而是任务说明书；
2. 用户输入只是上下文的一层；
3. Skill 是可复用的专业工作流程；
4. `AGENTS.md` 保存项目长期规则；
5. 当前会话摘要和跨会话记忆不能代替稳定项目规则；
6. 好提示词提高命中率，但不能保证结果正确。

#### 课堂练习

把下面的提示词改成六段式提示词：

> 帮我根据销售数据做一个 PPT。

学员至少补充：汇报对象、业务目标、数据材料、工作步骤、交付格式和检查要求。

#### 学员产出

一份可以直接交给 AI 的六段式提示词。

#### 细化程度

- **提示词：A 级，必须会写；**
- **上下文、Skill、`AGENTS.md`：B 级，能解释区别并知道怎么使用；**
- Skill 内部目录、上下文窗口数字、系统指令优先级只作补充，不展开。

配套讲义：

- [[AI办公课/03-为什么大模型需要提示词|为什么大模型需要提示词]]
- [[AI办公课/04-Skill与AGENTS如何进入AI上下文|Skill 与 AGENTS 如何进入 AI 上下文]]

### 第 3 块：需求商讨与 Markdown 固化（25～40 分钟）

#### 教学目标

让学员学会在生成文件之前，先让 AI 提问并把模糊需求变成一份双方确认的 Markdown 需求卡。

#### 分钟安排

| 时间 | 内容 |
|---|---|
| 25～28 分钟 | 明确业务目标、使用对象和需要推动的决定 |
| 28～33 分钟 | 让 AI 提出不超过 5 个关键问题 |
| 33～37 分钟 | 确认数据来源、时间范围、字段、维度、指标与口径 |
| 37～40 分钟 | 用 Markdown 固化需求并由用户确认 |

#### 需求卡必须包含

```text
业务目标：
使用对象：
数据来源：
统计范围：
关键字段：
分析维度：
核心指标与计算口径：
Excel 交付要求：
PPT 交付要求：
敏感信息处理方式：
待确认问题：
```

#### 学员产出

一份经过确认的 Markdown 需求卡，它将同时作为 Excel 和 PPT 的上游依据。

#### 细化程度

- **A 级，必须完成一次；**
- 必须分清字段、维度、指标和筛选条件；
- Markdown 只讲标题、清单、表格和待办；
- HTML 暂时不出现，避免打断需求思考。

### 第 4 块：从数据到 Excel 报表（40～60 分钟）

#### 教学目标

让学员看到 AI 如何根据“数据材料 + Markdown 需求卡”生成报表，并完成基础校验。

#### 分钟安排

| 时间 | 内容 |
|---|---|
| 40～44 分钟 | 检查原始数据、文件范围和敏感信息 |
| 44～49 分钟 | 先用 Markdown 规划工作表、字段、公式和汇总结构 |
| 49～55 分钟 | 生成或填写 Excel 报表 |
| 55～60 分钟 | 检查空值、重复、格式、公式、汇总和异常值 |

#### 建议演示数据

- 使用 10～20 行门店销售模拟数据；
- 字段包括日期、门店、地区、产品、销售额、成本和目标；
- 故意放入一个空值、一个重复行和一个格式错误；
- 让 AI 发现问题并记录处理方式。

#### 必须检查

- 数据是否完整；
- 同一字段格式是否一致；
- 是否存在重复或异常；
- 总计是否等于明细之和；
- 利润率、完成率等公式是否使用正确口径；
- PPT 中要使用的数字能否追溯到 Excel。

#### 学员产出

一份 Excel 报表，以及一份 AI 给出的检查结果和待人工确认项。

#### 细化程度

- 不讲工作簿、单元格等基础操作；
- 不讲复杂函数、宏、VBA；
- 重点讲“先规划、再生成、后验证”；
- 至少人工复算一个指标。

### 第 5 块：从 Excel 到 PPT 方案（60～75 分钟）

#### 教学目标

让学员理解 PPT 不是复制表格，而是用数据证据回答业务问题。

#### 分钟安排

| 时间 | 内容 |
|---|---|
| 60～64 分钟 | 从 Excel 中找出趋势、差异、异常与机会 |
| 64～68 分钟 | 使用汇报四问组织结论 |
| 68～72 分钟 | 用 Markdown 编写 5 页 PPT 页面方案 |
| 72～75 分钟 | 选择图表；简单说明 HTML 预览用途 |

#### 汇报四问

1. 发生了什么？
2. 为什么发生？
3. 意味着什么？
4. 接下来做什么？

#### Markdown PPT 方案格式

| 页码 | 页面标题 | 核心结论 | 数据依据 | 建议图表 | 行动建议 |
|---|---|---|---|---|---|
| 1 | 汇报目标与范围 | 本次汇报关注什么 | 统计范围 | KPI 卡片 | - |
| 2 | 整体经营结果 | 最重要的总体结论 | Excel 汇总 | 柱状图/折线图 | - |
| 3 | 关键差异 | 哪些门店或产品造成差异 | 分组数据 | 对比图 | - |
| 4 | 风险与机会 | 需要关注什么 | 异常数据 | 散点图/表格 | - |
| 5 | 下一步行动 | 谁在什么时候做什么 | 前述结论 | 行动清单 | 负责人和时间 |

#### 学员产出

一份不超过 5 页的 Markdown PPT 方案。

#### 细化程度

- **一页一个结论必须会；**
- 图表选择讲到“比较、趋势、占比、关系”即可；
- HTML 只作为视觉预览的辅助方案；
- DTD 最多用一句话说明，不进入实操。

### 第 6 块：生成并检查 PPT（75～85 分钟）

#### 教学目标

让学员完成从方案到 PPT 初稿，并知道怎样检查它是否可以交付。

#### 分钟安排

| 时间 | 内容 |
|---|---|
| 75～79 分钟 | 使用需求 Markdown、Excel 数据和页面方案生成 PPT |
| 79～83 分钟 | 检查数据、结构、标题、图表和版式 |
| 83～85 分钟 | 修改一页问题页面，展示迭代过程 |

#### PPT 检查清单

- [ ] 每一页都有明确结论；
- [ ] 标题表达观点，不只是写“数据分析”；
- [ ] 所有关键数字与 Excel 一致；
- [ ] 图表类型与数据关系匹配；
- [ ] 页面没有大段文字和无法阅读的表格；
- [ ] 建议能够对应前面的数据结论；
- [ ] 文件能够正常打开、翻页和展示。

#### 学员产出

一份 PPT 初稿，以及一份交付前检查清单。

#### 细化程度

- 不展开专业设计理论；
- 重点检查数据正确、叙事清楚和页面可读；
- 至少演示一次“发现问题 → 修改提示词 → 重新生成”。

### 第 7 块：复盘与迁移（85～90 分钟）

#### 教学目标

帮助学员把课堂案例变成下次可以复用的工作流程。

#### 分钟安排

| 时间 | 内容 |
|---|---|
| 85～87 分钟 | 全班复述完整工作链 |
| 87～89 分钟 | 展示交付前总检查清单 |
| 89～90 分钟 | 布置课后任务和结束 |

#### 最终复盘

```mermaid
flowchart LR
    A[提示词] --> B[需求商讨]
    B --> C[Markdown 需求卡]
    C --> D[Excel 报表]
    D --> E[数据校验与结论]
    E --> F[Markdown PPT 方案]
    F --> G[PPT 生成与复核]
```

#### 课后任务

选择一个自己的办公场景，用同样路线完成：

1. 一份需求卡；
2. 一份数据或报表；
3. 三个核心结论；
4. 一份 5 页以内的 PPT 方案。

## 六、讲师课前准备

### 必须准备

- [ ] 一份 10～20 行的模拟销售数据；
- [ ] 一份故意包含空值、重复和格式错误的数据；
- [ ] 一份完成版 Excel；
- [ ] 一份 5 页以内的完成版 PPT；
- [ ] 六段式提示词模板；
- [ ] Markdown 需求卡模板；
- [ ] Excel 与 PPT 检查清单；
- [ ] AI 工具、表格 Skill 和 PPT Skill 可正常使用。

### 课堂风险预案

| 风险 | 预案 |
|---|---|
| 文件生成耗时 | 准备完成版文件，生成过程只演示关键步骤 |
| AI 输出不稳定 | 准备一版可直接复制的标准提示词 |
| 数据错误太多 | 使用 10～20 行小样，不直接上大文件 |
| 时间不足 | 缩短 HTML 介绍，不删需求商讨和结果校验 |
| 学员跟不上 | 让学员只完成需求卡和提示词，文件生成由讲师演示 |

## 七、内容取舍原则

### 时间不够时不能删除

- 为什么需要提示词；
- 需求商讨；
- Markdown 需求卡；
- Excel 数据与公式校验；
- PPT 一页一个结论；
- 人工最终复核。

### 时间不够时可以压缩

- Skill 与 `AGENTS.md` 的技术细节；
- 上下文窗口和记忆机制；
- HTML 视觉预览；
- DTD；
- 专业 PPT 设计理论；
- 复杂 Excel 函数。

## 八、一句话总结

> [!quote]
> 这节课不是教用户分别操作 Excel 和 PPT，而是教用户如何让 AI 把“业务需求”转化成“可信数据”，再把“可信数据”转化成“可行动的汇报”。
