# 第一课｜纯前端 Vibe Coding：做出你的第一个网页

> [!abstract] 课程定位
> 这不是一节前端语法课，而是一节以实践为主的 Vibe Coding 创作课。概念只讲到“能够看懂技术地图、能够正确描述需求”为止，把更多时间留给学生自由创作。

## 一、课程目标

本节课结束后，学生应该能够：

- 用自己的话解释 HTML、CSS 和 JavaScript 分别负责什么。
- 大致分清 React、Vue、Angular、Node.js、Vite 和组件库。
- 知道企业组件库、动画库和酷炫组件集合的区别。
- 知道本课程为什么选择一套统一的前端技术路线。
- 向 AI 说清楚自己想做的页面、风格、内容和交互。
- 在 AI 的帮助下完成一个可以在浏览器中打开的个人导航页。
- 对作品进行至少一次主动修改，而不只是接受 AI 的第一次生成结果。

## 二、90 分钟课程节奏

| 环节 | 时间 | 目标 |
|---|---:|---|
| 开场与作品预览 | 5 分钟 | 让学生先看到今天能做出的结果 |
| 前端基础概念 | 10 分钟 | 认识 HTML、CSS、JavaScript |
| 前端生态与组件灵感 | 10 分钟 | 分清框架、工具、组件库和动画方案 |
| 教师现场示范 | 10 分钟 | 展示如何把想法交给 AI 并运行页面 |
| 学生自由创作 | 40 分钟 | 完成自己的导航页并持续迭代 |
| 作品展示与互评 | 10 分钟 | 分享创意、发现差异、互相借鉴 |
| 总结与下节课预告 | 5 分钟 | 固化认知并连接到浏览器插件 |

> [!tip] 授课原则
> 概念讲解控制在 20～25 分钟。学生一旦理解“每种工具负责什么”，就进入实践，不展开语法、底层原理和复杂工程知识。

### 第 2 页｜今天不是来背代码的

**页面内容：**

今天只完成一件事：

> 把你脑海中的一个页面，变成浏览器里真正可以打开的作品。

你将经历：

```text
提出想法 → 描述需求 → AI 生成 → 浏览器查看 → 继续修改
```

**讲师提示：**

- 降低学生对“编程”的恐惧。
- 明确 AI 可以帮助生成代码，但创意、选择和验收仍然由学生负责。
- 先展示最终效果，再开始讲概念。

### 第 3 页｜浏览器最终只认识三样东西

**页面内容：**

```text
HTML：房子的结构，决定页面里有什么
CSS：房子的装修，决定颜色、间距、大小和排版
JavaScript：电器和机关，决定点击以后发生什么
```

**举例：**

| 网页内容 | 谁负责 |
|---|---|
| 标题、搜索框、网站卡片 | HTML |
| 背景、圆角、颜色、布局 | CSS |
| 搜索、切换主题、点击交互 | JavaScript |

**讲师提示：**

这一页只建立直觉，不介绍标签、选择器、变量或函数。

### 第 4 页｜同一个页面，可以不断升级

**页面内容：**

```text
只有 HTML
页面有内容，但比较朴素

加入 CSS
页面开始有设计感

加入 JavaScript
页面可以搜索、切换和响应点击
```

**现场演示建议：**

用同一个网站卡片快速展示：

1. 只有文字和链接。
2. 加入颜色、圆角和阴影。
3. 加入鼠标悬停或点击反馈。

### 第 5 页｜为什么后来出现了前端框架

**页面内容：**

当页面只有几个元素时，直接编写 HTML、CSS 和 JavaScript 就够了。

当页面逐渐拥有：

- 大量重复卡片。
- 多个页面区域。
- 搜索和筛选。
- 弹窗和设置。
- 不断变化的数据。

代码就需要一种更容易组织的方式。

**核心结论：**

> React、Vue 和 Angular 的重要价值，是帮助我们把复杂页面拆成可复用的组件。

**讲师提示：**

用“乐高零件”解释组件，不展开响应式原理、虚拟 DOM 等内容。

---

### 第 6 页｜现代前端是一套组合，不是一个工具

**页面内容：**

```text
用户看到的页面
        ↓
组件库：现成的按钮、卡片、弹窗
        ↓
前端框架：React / Vue / Angular
        ↓
Web 基础：HTML + CSS + JavaScript
        ↓
开发工具：Node.js + npm + Vite
```

**需要讲清楚的三个区别：**

- React、Vue、Angular：负责组织页面。
- Node.js：让现代前端开发工具能够运行。
- 组件库：提供可以直接使用的页面零件。

---

### 第 7 页｜React、Vue、Angular 是三条不同路线

**页面内容：**

| 技术 | 一句话理解 | 常见生态 | 更适合 |
|---|---|---|---|
| React | 自由组合的 UI 积木 | Vite、Next.js、MUI、Ant Design、shadcn/ui | 独立产品、丰富交互、Vibe Coding |
| Vue | 比较直观的渐进式框架 | Vite、Nuxt、Pinia、Element Plus、Vuetify | 中小项目、中文开发者、渐进学习 |
| Angular | 规范完整的一整套工程体系 | Angular CLI、Angular Material、PrimeNG | 大型团队、复杂企业项目 |

**简短历史脉络：**

```text
早期静态页面
→ jQuery 与网页插件
→ 组件化时代
→ React / Vue / Angular
→ 更完整的网站框架与工具链
```

**讲师提示：**

- 不比较性能，不讨论“谁最好”。
- 只让学生知道它们解决的问题相似，但路线和生态不同。
- Angular 只介绍，不作为本课实践技术。

---

### 第 8 页｜Node.js、npm、Vite 分别是什么

**页面内容：**

```text
npm：安装项目需要的工具和组件
Node.js：让这些开发工具在电脑上运行
Vite：启动项目，并把项目打包成网页文件
```

**生活化比喻：**

- npm：建材市场。
- Node.js：施工环境。
- Vite：帮助开工和交付的施工工具。

**讲师提示：**

本节课不讲 Node.js 后端，也不要求学生理解命令原理。学生只需要知道：看到 `npm run dev`，是在启动项目。

---

### 第 9 页｜CSS 工具和组件库不是一回事

**页面内容：**

| 类型 | 代表工具 | 可以理解为 |
|---|---|---|
| 原生 CSS | CSS | 自己设计和装修 |
| CSS 工具框架 | Tailwind CSS | 一盒样式积木 |
| 完整 UI 框架 | Bootstrap | 带基础样式的成套零件 |
| React 组件库 | MUI、Ant Design | React 的成品家具 |
| Vue 组件库 | Element Plus、Vuetify | Vue 的成品家具 |
| 开放组件代码 | shadcn/ui | 把家具图纸和源码交给你 |

**核心结论：**

> Tailwind 主要帮助我们控制样式；组件库则同时提供外观和交互。

---

### 第 10 页｜大厂组件库让产品快速达到“可用”

**页面内容：**

| 来源 | 代表方案 | 更擅长 |
|---|---|---|
| 蚂蚁集团 | Ant Design | 表格、表单、后台和企业产品 |
| 蚂蚁集团 | Ant Design X | AI 对话、消息气泡、引用和流式内容 |
| 阿里体系 | Fusion Design | 企业中后台和品牌主题 |
| 字节跳动 | Semi Design | 现代企业应用、SaaS 和内容平台 |
| 字节跳动 | Arco Design | 企业组件、主题与物料体系 |

**核心结论：**

> 大厂组件库主要解决“完整、统一、可靠”，不等于“动画特别酷炫”。

**讲师提示：**

- Ant Design 更准确地说来自蚂蚁集团和开源社区，而不是直接归为阿里组件库。
- 只快速展示官网效果，不展开安装和 API。
- 说明第一课不会同时使用多套完整组件库。

---

### 第 11 页｜动画库负责让组件“动起来”

**页面内容：**

| 想要的效果 | 推荐方案 |
|---|---|
| 简单悬停和颜色变化 | CSS Transition |
| 卡片进出、拖拽、布局变化 | Motion |
| 列表添加、删除和排序 | AutoAnimate |
| 复杂时间线和滚动叙事 | GSAP |
| 弹簧和物理运动 | React Spring |
| 互动插画 | Rive / Lottie |
| 三维场景 | React Three Fiber |

**本课推荐：**

```text
基础动画优先使用 Motion
列表变化可以使用 AutoAnimate
GSAP 和 3D 只作为进阶方向展示
```

**核心结论：**

> 动画不是越多越好，而是要让点击、切换和页面变化更容易理解。

---

### 第 12 页｜酷炫组件可以成为作品的视觉亮点

**页面内容：**

| 方案 | 视觉特点 | 适合加入导航页的效果 |
|---|---|---|
| React Bits | 创意、实验感强 | 极光背景、动态文字、聚光卡片 |
| Magic UI | 独立站和产品官网风格 | Bento Grid、Dock、光束、粒子 |
| Aceternity UI | 科技感和视觉冲击力强 | 3D 卡片、视差、聚光灯、动态边框 |
| Animate UI | 基于 Motion 的开放动画组件 | 动画弹窗、菜单、图标和基础交互 |
| shadcn/ui | 简洁、可修改的产品组件 | 输入框、按钮、对话框、侧边栏 |

**创作规则：**

```text
一套基础组件体系
+ 一个动画方案
+ 最多两个视觉亮点
```

**讲师提示：**

现场只展示几个有代表性的组件，让学生产生创作灵感，不逐个讲解组件名称。

---

### 第 13 页｜这门课选择一条简单的实践路线

**页面内容：**

```text
React
+ Vite
+ Tailwind CSS
+ Motion 作为默认动画方案
+ 必要时使用少量 shadcn/ui
+ 自选一个酷炫视觉组件
```

它们分别负责：

- React：把导航页拆成组件。
- Vite：启动和打包项目。
- Tailwind CSS：完成页面视觉设计。
- Motion：完成卡片进入、悬停和切换动画。
- shadcn/ui：需要弹窗、输入框等组件时再使用。
- React Bits 或 Magic UI：只选择一个效果作为视觉亮点。

**为什么这样选：**

- AI 对这套生态比较熟悉。
- 适合自由创作不同风格的页面。
- 可以生成纯前端网站。
- 后续能够继续改造成 Chrome / Edge 新标签页插件。

**讲师提示：**

强调“这是本课程选择的一条路线”，不是要求学生判断所有技术优劣。

### 第 14 页｜现场示范：把一句想法变成页面

**第一轮提示词：**

> 使用 React、Vite 和 Tailwind CSS 创建一个个人导航页。页面顶部显示标题和搜索框，下面按照学习、工作、娱乐三个分类展示网站卡片。整体使用简洁的浅色风格，暂时不使用后端。

**第二轮提示词：**

> 保留现有结构和功能，使用 Motion 为网站卡片增加依次进入、鼠标悬停和点击反馈。再加入一个低强度的动态背景作为视觉亮点，确保文字清楚、手机端可以正常使用。

**示范流程：**

```text
说出想法
→ AI 创建项目
→ 启动项目
→ 浏览器查看
→ 找到一个不满意的地方
→ 继续让 AI 修改
```

**示范重点：**

- 不追求一次生成完美结果。
- 展示如何说清楚“只修改哪里”。
- 演示“基础页面完成后，再增加动画和视觉组件”的顺序。
- 展示修改以后一定要回到浏览器检查。

### 第 15 页｜你的创作任务：设计自己的首页

**基础要求：**

- 一个页面标题。
- 一个搜索框。
- 至少三个导航分类。
- 每个分类至少三个网站入口。
- 点击卡片可以打开对应网站。
- 页面能够正常在浏览器中运行。

**自由创作部分：**

学生可以自由决定：

- 页面主题。
- 色彩和字体。
- 背景和插画。
- 卡片形状。
- 分类方式。
- 欢迎语。
- 是否加入时间、天气、待办或每日一句。

学生还可以选择一种增强方案：

- 产品风：shadcn/ui + Motion。
- 酷炫风：React Bits + Motion。
- 独立站风：Magic UI + Motion。
- 企业产品风：Ant Design、Semi Design 或 Arco Design 三选一。

> [!important] 创作要求
> 必须在 AI 第一次生成结果的基础上，完成至少两轮自己主动提出的修改。

> [!warning] 组件限制
> 只选择一套基础组件体系、一个动画方案和最多两个视觉亮点，不要在同一页面混用多套完整组件库。

### 第 16 页｜不知道做什么，可以从这些主题开始

**创作方向：**

- 学习导航：课程、工具、资料和 AI 网站。
- 工作首页：邮箱、文档、项目和常用系统。
- 设计师首页：灵感、配色、字体和素材网站。
- 旅行首页：地图、攻略、酒店和行程。
- 游戏玩家首页：游戏、直播、社区和攻略。
- 极简首页：时间、搜索和少量常用入口。
- 赛博朋克首页：深色背景、霓虹色和动态效果。
- 治愈系首页：柔和配色、插画和每日一句。

**讲师提示：**

鼓励学生彼此做出不同作品，不提供唯一标准答案。

### 第 17 页｜让 AI 听懂你的四个问题

**提示词结构：**

```text
1. 我要做什么？
2. 页面里有什么？
3. 希望它长什么样？
4. 用户可以做什么？
```

**示例：**

> 我要做一个治愈系个人导航页。顶部显示“晚上好”，中间放一个搜索框，下面展示学习、工作和放松三个分类。使用米白色背景、浅绿色和橙色作为强调色，卡片圆润并带轻微阴影。点击网站卡片后在新标签页打开对应网站。

**进一步修改时：**

- 只把背景改成深色，不修改页面结构。
- 把网站卡片改成每行四张。
- 手机端改成每行两张卡片。
- 保留现有功能，增加深色模式按钮。
- 使用 Motion 为卡片增加轻微的进入和悬停动画。
- 使用 React Bits 或 Magic UI 增加一个背景效果，不改变现有内容。

### 第 18 页｜自由创作时的检查点

**完成第一版后检查：**

- 页面能否正常打开？
- 搜索框和网站链接能否使用？
- 页面有没有明显错位？
- 卡片上的文字是否清楚？
- 风格是否符合自己的设想？
- 动画是否影响文字阅读或页面操作？
- 手机尺寸下是否仍然可用？
- 有没有完成至少两轮主动修改？

**如果出现问题：**

交给 AI：

```text
当前效果截图
+ 完整错误信息
+ 你原本希望看到的效果
+ 明确要求保留的内容
```

### 第 19 页｜作品展示：没有唯一正确答案

**每位展示者回答三个问题：**

1. 你做的是什么主题？
2. 你主动要求 AI 修改了什么？
3. 下一步你还想增加什么？

**互评关注点：**

- 创意是否鲜明。
- 页面是否容易使用。
- 视觉是否统一。
- 哪个细节最值得借鉴。

**讲师提示：**

不要用“代码是否高级”评价作品，重点评价表达、选择、迭代和完成度。

**页面内容：**

```text
今天：做出可以运行的个人导航页
下一步：优化页面并部署为独立站
```

## 四、学生自由创作阶段的教师巡回答疑

实践阶段建议优先检查以下问题：

### 1. 项目是否真的运行起来

- 学生是否打开了正确的项目目录。
- 开发服务是否已经启动。
- 浏览器地址是否正确。
- AI 是否把代码写进了正确文件。

### 2. 学生是否在表达自己的想法

- 是否只是接受默认模板。
- 是否能说出自己想要的主题和视觉风格。
- 是否提出了至少两次主动修改。
- 是否能判断修改结果是否符合预期。

### 3. 及时控制功能范围

第一节课暂时不建议加入：

- 用户登录。
- 云端数据库。
- 支付功能。
- 复杂后台。
- 多人协作。
- 跨设备同步。
- 需要密钥的第三方接口。

如果学生提出复杂想法，可以记录到“下一版本”，先保证基础页面完成。

### 4. 控制组件与动画数量

- 是否只使用了一套基础组件体系。
- 是否因为重复引入组件库造成风格冲突。
- AI 是否补全了新组件需要的依赖。
- 动画是否影响阅读、点击和页面性能。
- 鼠标特效在手机端是否能够自动关闭或正常退化。
- 学生是否为了“酷炫”加入了过多无关效果。

## 五、时间不足时的删减顺序

如果现场实践需要更多时间，可以依次压缩：

1. 第 7 页框架生态只讲 React、Vue、Angular 的一句话区别。
2. 第 8 页只保留“Node.js 运行工具，npm 安装工具，Vite 启动项目”。
3. 第 9 页只比较 Tailwind 和组件库。

### 附录 F｜React 动画方案

#### Motion

原名 Framer Motion，目前推荐从 `motion/react` 导入。

适合：

- 元素进入和退出。
- 卡片悬停和点击反馈。
- 拖拽与手势。
- 布局变化和列表重排。
- 滚动触发动画。
- SVG 动画。

示例：

```jsx
<motion.div
  initial={{ opacity: 0, y: 20 }}
  animate={{ opacity: 1, y: 0 }}
  whileHover={{ scale: 1.03 }}
  whileTap={{ scale: 0.97 }}
>
  网站卡片
</motion.div>
```

本课把 Motion 作为 React 基础动画的首选。

#### AutoAnimate

定位：几乎零配置的列表动画工具。

适合：

- 添加或删除网站卡片。
- 列表自动排序。
- 分类切换。
- 待办事项列表。

优点是上手简单；不足是对复杂动画过程的精细控制较少。

#### GSAP

定位：专业级 JavaScript 动画和时间线工具。

适合：

- 多元素动画编排。
- 滚动叙事和视差效果。
- SVG、Canvas、Three.js 和 WebGL。
- 品牌发布页和沉浸式网站。

React 中可以配合 `@gsap/react` 的 `useGSAP()`，帮助处理作用域和组件卸载时的动画清理。

第一课只做效果展示，不要求学生使用。

#### React Spring

定位：以弹簧物理模型为核心的 React 动画方案。

适合拖拽回弹、有重量感的卡片和自然的数据变化。第一课不建议与 Motion 同时引入。

#### Lottie、Rive 与 React Three Fiber

| 方案 | 适合场景 | 第一课建议 |
|---|---|---|
| Lottie | 加载、成功提示和动画插画 | 可以少量使用 |
| Rive | 可交互吉祥物、状态机动画 | 作为进阶方向 |
| React Three Fiber | 3D 地球、产品模型和粒子场景 | 只展示，不实践 |

特点：基于 Tailwind CSS、Motion 和 shadcn Registry 的开放动画组件集合。

适合：

- 希望直接获得组件源代码并让 AI 修改的项目。

#### shadcn/ui

定位：开放代码的基础产品组件体系，本身不以炫技动画为核心。

推荐组合：

### 附录 I｜组件与动画提示词

#### 基础动画

> 当前项目使用 React、Vite 和 Tailwind CSS。请使用 Motion 为网站卡片增加依次淡入和向上移动的进入动画。鼠标经过时卡片放大到 1.03，点击时缩小到 0.97。保留现有页面结构和链接，不要修改其他功能，并支持减少动态效果的系统设置。

#### 酷炫导航页

> 保留当前 React 导航页的内容，使用 React Bits 风格增加一个低强度的动态极光背景，并为卡片增加跟随鼠标的聚光效果。动画不能影响文字阅读，手机端关闭鼠标跟随效果。

#### 独立站风格

> 使用 Magic UI 风格优化首页。使用 Bento Grid 展示网站分类，使用 Dock 展示最常用的五个入口，并为标题增加轻微的文字动画。不要添加与导航功能无关的复杂内容。

#### 企业产品风格

> 使用 Semi Design 的输入框、按钮、卡片和弹窗组件重构当前页面。保持浅色、简洁、现代的企业产品风格，不要同时引入其他完整组件库。

### 附录 J｜使用组件和动画的四条规则

1. 一页只需要一个主要视觉亮点。
2. 一套基础组件体系、一个动画方案、最多两个特殊效果。
3. 所有动画都要检查手机端、低性能设备和减少动态效果设置。
4. 让 AI 在安装前核对官方文档、依赖名称、当前版本和授权方式。
