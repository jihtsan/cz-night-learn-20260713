# 第一课｜纯前端 Vibe Coding：做出你的第一个网页

> [!abstract] 课程定位
> 这不是一节前端语法课，而是一节以实践为主的 Vibe Coding 创作课。概念只讲到“能够看懂技术地图、能够正确描述需求”为止，把更多时间留给学生自由创作。

## 一、课程目标

本节课结束后，学生应该能够：

- 用自己的话解释 HTML、CSS 和 JavaScript 分别负责什么。
- 大致分清 React、Vue、Angular、Node.js、Vite 和组件库。
- 知道本课程为什么选择一套统一的前端技术路线。
- 向 AI 说清楚自己想做的页面、风格、内容和交互。
- 在 AI 的帮助下完成一个可以在浏览器中打开的个人导航页。
- 对作品进行至少一次主动修改，而不只是接受 AI 的第一次生成结果。

## 二、90 分钟课程节奏

| 环节 | 时间 | 目标 |
|---|---:|---|
| 开场与作品预览 | 5 分钟 | 让学生先看到今天能做出的结果 |
| 前端基础概念 | 10 分钟 | 认识 HTML、CSS、JavaScript |
| 现代前端生态地图 | 10 分钟 | 分清框架、工具和组件库的位置 |
| 教师现场示范 | 10 分钟 | 展示如何把想法交给 AI 并运行页面 |
| 学生自由创作 | 40 分钟 | 完成自己的导航页并持续迭代 |
| 作品展示与互评 | 10 分钟 | 分享创意、发现差异、互相借鉴 |
| 总结与下节课预告 | 5 分钟 | 固化认知并连接到浏览器插件 |

> [!tip] 授课原则
> 概念讲解控制在 20～25 分钟。学生一旦理解“每种工具负责什么”，就进入实践，不展开语法、底层原理和复杂工程知识。

## 三、核心 PPT 大纲

### 第 1 页｜封面

**标题：**

纯前端 Vibe Coding：做出你的第一个网页

**副标题：**

不用先学会写代码，也可以开始创造

**画面建议：**

展示 3～4 个不同风格的个人导航页，让学生一开始就知道今天的作品可以有很大差异。

---

### 第 2 页｜今天不是来背代码的

**页面内容：**

今天只完成一件事：

> 把你脑海中的一个页面，变成浏览器里真正可以打开的作品。

你将经历：

```text
提出想法 → 描述需求 → AI 生成 → 浏览器查看 → 继续修改
```

**讲师提示：**

- 降低学生对“编程”的恐惧。
- 明确 AI 可以帮助生成代码，但创意、选择和验收仍然由学生负责。
- 先展示最终效果，再开始讲概念。

---

### 第 3 页｜浏览器最终只认识三样东西

**页面内容：**

```text
HTML：房子的结构，决定页面里有什么
CSS：房子的装修，决定颜色、间距、大小和排版
JavaScript：电器和机关，决定点击以后发生什么
```

**举例：**

| 网页内容 | 谁负责 |
|---|---|
| 标题、搜索框、网站卡片 | HTML |
| 背景、圆角、颜色、布局 | CSS |
| 搜索、切换主题、点击交互 | JavaScript |

**讲师提示：**

这一页只建立直觉，不介绍标签、选择器、变量或函数。

---

### 第 4 页｜同一个页面，可以不断升级

**页面内容：**

```text
只有 HTML
页面有内容，但比较朴素

加入 CSS
页面开始有设计感

加入 JavaScript
页面可以搜索、切换和响应点击
```

**现场演示建议：**

用同一个网站卡片快速展示：

1. 只有文字和链接。
2. 加入颜色、圆角和阴影。
3. 加入鼠标悬停或点击反馈。

---

### 第 5 页｜为什么后来出现了前端框架

**页面内容：**

当页面只有几个元素时，直接编写 HTML、CSS 和 JavaScript 就够了。

当页面逐渐拥有：

- 大量重复卡片。
- 多个页面区域。
- 搜索和筛选。
- 弹窗和设置。
- 不断变化的数据。

代码就需要一种更容易组织的方式。

**核心结论：**

> React、Vue 和 Angular 的重要价值，是帮助我们把复杂页面拆成可复用的组件。

**讲师提示：**

用“乐高零件”解释组件，不展开响应式原理、虚拟 DOM 等内容。

---

### 第 6 页｜现代前端是一套组合，不是一个工具

**页面内容：**

```text
用户看到的页面
        ↓
组件库：现成的按钮、卡片、弹窗
        ↓
前端框架：React / Vue / Angular
        ↓
Web 基础：HTML + CSS + JavaScript
        ↓
开发工具：Node.js + npm + Vite
```

**需要讲清楚的三个区别：**

- React、Vue、Angular：负责组织页面。
- Node.js：让现代前端开发工具能够运行。
- 组件库：提供可以直接使用的页面零件。

---

### 第 7 页｜React、Vue、Angular 是三条不同路线

**页面内容：**

| 技术 | 一句话理解 | 常见生态 | 更适合 |
|---|---|---|---|
| React | 自由组合的 UI 积木 | Vite、Next.js、MUI、Ant Design、shadcn/ui | 独立产品、丰富交互、Vibe Coding |
| Vue | 比较直观的渐进式框架 | Vite、Nuxt、Pinia、Element Plus、Vuetify | 中小项目、中文开发者、渐进学习 |
| Angular | 规范完整的一整套工程体系 | Angular CLI、Angular Material、PrimeNG | 大型团队、复杂企业项目 |

**简短历史脉络：**

```text
早期静态页面
→ jQuery 与网页插件
→ 组件化时代
→ React / Vue / Angular
→ 更完整的网站框架与工具链
```

**讲师提示：**

- 不比较性能，不讨论“谁最好”。
- 只让学生知道它们解决的问题相似，但路线和生态不同。
- Angular 只介绍，不作为本课实践技术。

---

### 第 8 页｜Node.js、npm、Vite 分别是什么

**页面内容：**

```text
npm：安装项目需要的工具和组件
Node.js：让这些开发工具在电脑上运行
Vite：启动项目，并把项目打包成网页文件
```

**生活化比喻：**

- npm：建材市场。
- Node.js：施工环境。
- Vite：帮助开工和交付的施工工具。

**讲师提示：**

本节课不讲 Node.js 后端，也不要求学生理解命令原理。学生只需要知道：看到 `npm run dev`，是在启动项目。

---

### 第 9 页｜CSS 工具和组件库不是一回事

**页面内容：**

| 类型 | 代表工具 | 可以理解为 |
|---|---|---|
| 原生 CSS | CSS | 自己设计和装修 |
| CSS 工具框架 | Tailwind CSS | 一盒样式积木 |
| 完整 UI 框架 | Bootstrap | 带基础样式的成套零件 |
| React 组件库 | MUI、Ant Design | React 的成品家具 |
| Vue 组件库 | Element Plus、Vuetify | Vue 的成品家具 |
| 开放组件代码 | shadcn/ui | 把家具图纸和源码交给你 |

**核心结论：**

> Tailwind 主要帮助我们控制样式；组件库则同时提供外观和交互。

---

### 第 10 页｜这门课选择一条简单的实践路线

**页面内容：**

```text
React
+ Vite
+ Tailwind CSS
+ 必要时使用少量 shadcn/ui
```

它们分别负责：

- React：把导航页拆成组件。
- Vite：启动和打包项目。
- Tailwind CSS：完成页面视觉设计。
- shadcn/ui：需要弹窗、输入框等组件时再使用。

**为什么这样选：**

- AI 对这套生态比较熟悉。
- 适合自由创作不同风格的页面。
- 可以生成纯前端网站。
- 后续能够继续改造成 Chrome / Edge 新标签页插件。

**讲师提示：**

强调“这是本课程选择的一条路线”，不是要求学生判断所有技术优劣。

---

### 第 11 页｜现场示范：把一句想法变成页面

**第一轮提示词：**

> 使用 React、Vite 和 Tailwind CSS 创建一个个人导航页。页面顶部显示标题和搜索框，下面按照学习、工作、娱乐三个分类展示网站卡片。整体使用简洁的浅色风格，暂时不使用后端。

**示范流程：**

```text
说出想法
→ AI 创建项目
→ 启动项目
→ 浏览器查看
→ 找到一个不满意的地方
→ 继续让 AI 修改
```

**示范重点：**

- 不追求一次生成完美结果。
- 展示如何说清楚“只修改哪里”。
- 展示修改以后一定要回到浏览器检查。

---

### 第 12 页｜你的创作任务：设计自己的首页

**基础要求：**

- 一个页面标题。
- 一个搜索框。
- 至少三个导航分类。
- 每个分类至少三个网站入口。
- 点击卡片可以打开对应网站。
- 页面能够正常在浏览器中运行。

**自由创作部分：**

学生可以自由决定：

- 页面主题。
- 色彩和字体。
- 背景和插画。
- 卡片形状。
- 分类方式。
- 欢迎语。
- 是否加入时间、天气、待办或每日一句。

> [!important] 创作要求
> 必须在 AI 第一次生成结果的基础上，完成至少两轮自己主动提出的修改。

---

### 第 13 页｜不知道做什么，可以从这些主题开始

**创作方向：**

- 学习导航：课程、工具、资料和 AI 网站。
- 工作首页：邮箱、文档、项目和常用系统。
- 设计师首页：灵感、配色、字体和素材网站。
- 旅行首页：地图、攻略、酒店和行程。
- 游戏玩家首页：游戏、直播、社区和攻略。
- 极简首页：时间、搜索和少量常用入口。
- 赛博朋克首页：深色背景、霓虹色和动态效果。
- 治愈系首页：柔和配色、插画和每日一句。

**讲师提示：**

鼓励学生彼此做出不同作品，不提供唯一标准答案。

---

### 第 14 页｜让 AI 听懂你的四个问题

**提示词结构：**

```text
1. 我要做什么？
2. 页面里有什么？
3. 希望它长什么样？
4. 用户可以做什么？
```

**示例：**

> 我要做一个治愈系个人导航页。顶部显示“晚上好”，中间放一个搜索框，下面展示学习、工作和放松三个分类。使用米白色背景、浅绿色和橙色作为强调色，卡片圆润并带轻微阴影。点击网站卡片后在新标签页打开对应网站。

**进一步修改时：**

- 只把背景改成深色，不修改页面结构。
- 把网站卡片改成每行四张。
- 手机端改成每行两张卡片。
- 保留现有功能，增加深色模式按钮。

---

### 第 15 页｜自由创作时的检查点

**完成第一版后检查：**

- 页面能否正常打开？
- 搜索框和网站链接能否使用？
- 页面有没有明显错位？
- 卡片上的文字是否清楚？
- 风格是否符合自己的设想？
- 有没有完成至少两轮主动修改？

**如果出现问题：**

交给 AI：

```text
当前效果截图
+ 完整错误信息
+ 你原本希望看到的效果
+ 明确要求保留的内容
```

---

### 第 16 页｜作品展示：没有唯一正确答案

**每位展示者回答三个问题：**

1. 你做的是什么主题？
2. 你主动要求 AI 修改了什么？
3. 下一步你还想增加什么？

**互评关注点：**

- 创意是否鲜明。
- 页面是否容易使用。
- 视觉是否统一。
- 哪个细节最值得借鉴。

**讲师提示：**

不要用“代码是否高级”评价作品，重点评价表达、选择、迭代和完成度。

---

### 第 17 页｜今天，我们完成了第一个版本

**页面内容：**

```text
今天：做出可以运行的个人导航页
下一步：优化页面并部署为独立站
再下一步：改造成 Chrome / Edge 新标签页插件
```

**结尾话术：**

> Vibe Coding 不是让 AI 替你做决定，而是让你把更多精力放在想法、选择和迭代上。

## 四、学生自由创作阶段的教师巡回答疑

实践阶段建议优先检查以下问题：

### 1. 项目是否真的运行起来

- 学生是否打开了正确的项目目录。
- 开发服务是否已经启动。
- 浏览器地址是否正确。
- AI 是否把代码写进了正确文件。

### 2. 学生是否在表达自己的想法

- 是否只是接受默认模板。
- 是否能说出自己想要的主题和视觉风格。
- 是否提出了至少两次主动修改。
- 是否能判断修改结果是否符合预期。

### 3. 及时控制功能范围

第一节课暂时不建议加入：

- 用户登录。
- 云端数据库。
- 支付功能。
- 复杂后台。
- 多人协作。
- 跨设备同步。
- 需要密钥的第三方接口。

如果学生提出复杂想法，可以记录到“下一版本”，先保证基础页面完成。

## 五、时间不足时的删减顺序

如果现场实践需要更多时间，可以依次压缩：

1. 第 7 页框架生态只讲 React、Vue、Angular 的一句话区别。
2. 第 8 页只保留“Node.js 运行工具，npm 安装工具，Vite 启动项目”。
3. 第 9 页只比较 Tailwind 和组件库。
4. 第 13 页创作主题作为学生操作时的提示页循环展示。

不建议压缩：

- HTML、CSS、JavaScript 的基础认知。
- 教师现场示范。
- 学生自由创作。
- 作品展示与复盘。
