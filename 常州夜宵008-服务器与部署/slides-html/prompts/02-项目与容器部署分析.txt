一、检查项目

1. 先确认项目所在目录和需要分析的 Git 分支或版本。
2. 只读取判断技术栈所必需的文件，例如 README、package.json、锁文件、requirements.txt、pyproject.toml、pom.xml、build.gradle、Dockerfile、compose.yaml 和现有部署文档。
3. 不要读取或输出 .env、私钥、Token、数据库密码等敏感内容。如果需要环境变量，只列出变量名称，不显示变量值。
4. 判断项目属于纯静态网站、前端构建产物、Node.js、Python、Java JAR、Java WAR、PHP、.NET 或其他类型。
5. 找出构建命令、启动命令、监听地址、监听端口、健康检查地址、文件存储需求、数据库依赖、定时任务、后台任务和 WebSocket 需求。
6. 检查项目是否已有 Dockerfile、Compose、systemd、Nginx、Caddy、Tomcat 或持续部署配置；不要默认现有配置一定正确。

二、检查服务器

1. 只读检查操作系统、CPU 架构、CPU、内存、Swap、磁盘和当前负载。
2. 检查 Docker、Docker Compose、Podman、Nginx、Caddy、Tomcat 和项目运行时是否已经安装。
3. 检查当前运行的容器、监听端口、已有网站和服务配置，识别端口或域名冲突。
4. 不要停止、重启、删除或覆盖任何现有服务。

三、比较部署方案

请根据项目情况比较以下方案：

A. 直接运行，并用 systemd 管理
B. 单个 Docker 容器
C. Docker Compose 管理应用和反向代理
D. Nginx/Caddy 托管静态文件
E. JRE 运行 Spring Boot 可执行 JAR
F. Tomcat 运行 WAR
G. 其他更合适的方式

不要为了使用容器而强行使用容器。如果简单的 systemd 部署更合适，也可以推荐，但必须说明依据。

需要特别区分：

- Nginx/Caddy 常用于静态文件、HTTPS 和反向代理；
- Tomcat 是 Java Servlet 应用服务器，主要用于 WAR 等对应场景；
- Spring Boot 可执行 JAR 通常使用内置 HTTP 服务器，不要默认再增加外部 Tomcat；
- Docker/Podman 是容器运行工具，不等于 Nginx 或 Tomcat；
- Docker Compose 适合声明和管理多个相关服务、网络与数据卷。
