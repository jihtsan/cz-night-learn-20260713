# 电商管理后台需求大纲

## 1. 项目概述

### 1.1 建设目标

- 为运营、商品、仓储、客服、财务和管理员提供统一的业务管理后台。
- 覆盖商品从建档、售卖、履约到售后的核心流程，降低人工处理成本。
- 提供可追溯的数据、权限和操作记录，支持经营决策与风险控制。

### 1.2 目标用户与角色

| 角色 | 核心职责 |
| --- | --- |
| 超级管理员 | 组织、角色、权限、系统配置与审计管理 |
| 运营人员 | 商品运营、活动、优惠、内容及数据分析 |
| 商品人员 | 商品、类目、品牌、规格、价格和库存资料维护 |
| 仓储人员 | 入库、出库、盘点、调拨和发货处理 |
| 客服人员 | 订单查询、售后受理、退款与客户沟通 |
| 财务人员 | 对账、退款审核、结算及财务报表 |

### 1.3 范围说明

首期聚焦 B2C 自营电商后台；前台商城、支付渠道、物流公司、ERP/WMS/CRM 等系统通过接口集成。多店铺、多币种、多仓和供应商协同可作为后续扩展能力。

## 3. 功能需求

### 3.1 首页仪表盘

- 展示今日/本周期的销售额、支付订单数、客单价、退款额、访客与转化率等核心指标。
- 展示待办事项：待审核商品、待发货订单、库存预警、待处理售后和异常订单。
- 支持按店铺、渠道、时间范围筛选，并可跳转至对应业务列表。

### 3.2 商品中心

- 类目、品牌、属性和规格模板管理。
- SPU/SKU 新建、编辑、复制、上下架、批量导入导出和审核。
- 维护商品名称、图文详情、主图、售价、划线价、成本价、条码、重量及配送信息。
- 支持多规格组合、SKU 编码、商品标签、搜索关键词和渠道可见范围。
- 管理商品状态：草稿、待审核、已上架、已下架、已删除。

### 3.3 订单中心

- 按订单号、用户、商品、状态、渠道、时间和支付状态搜索订单。
- 查看订单详情：商品明细、收货信息、支付信息、优惠分摊、物流轨迹、操作记录。
- 支持订单确认、改价（需留痕）、拆单/合单、取消、备注、导出和异常标记。
- 管理订单状态流转：待付款、待确认、待发货、运输中、已完成、已关闭、售后中。
- 处理发货：选择仓库与物流、生成运单、批量发货、补发和拦截发货。

### 3.4 库存与仓储

- 仓库、库位、库存单位及库存预警阈值管理。
- 管理可售库存、锁定库存、在途库存与实际库存。
- 支持入库、出库、调拨、盘点、库存调整和报损；所有变动需记录原因与操作人。
- 订单支付、取消、发货、售后等事件自动联动库存。
- 提供低库存、超卖风险、滞销库存和库存流水查询。

### 3.5 营销中心

- 管理优惠券、满减/满折、限时折扣、秒杀、拼团等营销活动。
- 配置活动时间、适用商品/类目、库存、用户范围、叠加规则和预算上限。
- 支持活动审核、上下线、效果数据查看和异常预警。
- 支持首页推荐位、商品标签及专题页配置（如前台需要）。

### 3.6 会员与客服

- 查询会员基本资料、订单历史、优惠券、积分和会员标签。
- 支持会员分层、标签管理、黑名单及营销触达名单导出。
- 管理售后单：退款、退货退款、换货、补发；支持凭证上传、审核、物流回寄和退款状态跟踪。
- 支持客服备注、内部协作记录、快捷回复和工单分配。

### 3.7 财务中心

- 查看支付、退款、手续费、优惠承担与渠道结算明细。
- 支持按订单、支付渠道、店铺和账期对账，并标记差异与处理结果。
- 管理退款审核、结算单、发票信息和财务导出。
- 提供销售、退款、毛利等财务口径说明，确保与数据中心一致。

### 3.8 数据中心

- 销售分析：GMV、支付金额、订单量、客单价、退款率、毛利。
- 商品分析：商品排行、SKU 销量、转化、复购、滞销和缺货情况。
- 用户分析：新增、活跃、复购、消费分层和地域分布。
- 营销分析：活动参与、优惠成本、活动订单和投入产出。
- 支持图表筛选、明细下钻、定时报表及 CSV/XLSX 导出。

### 3.9 系统管理

- 组织、员工账号、角色和菜单/数据权限管理。
- 支持按店铺、仓库、业务模块和操作类型配置数据访问范围。
- 配置支付、物流、消息通知、订单超时、库存预警和售后规则。
- 提供操作日志、登录日志、数据导入导出记录和敏感操作审计。

## 4. 核心业务规则

- 库存扣减时点、库存锁定时点和订单超时释放规则须可配置并统一执行。
- 商品价格、优惠金额、运费和积分抵扣应在订单中固化，后续商品变更不得影响历史订单。
- 退款金额不得超过实际支付金额；退款与退货状态需独立追踪。
- 改价、库存调整、退款审核、权限变更等敏感操作必须记录操作人、时间、前后值及原因。
- 订单、售后和库存状态需使用统一状态机，禁止跨状态的非法操作。

## 5. 非功能需求

### 5.1 性能与可用性

- 常用列表和详情页面在正常负载下应在 3 秒内完成响应。
- 支持分页、筛选、排序、批量操作和异步导出，避免大数据量页面阻塞。
- 关键订单、支付与库存接口需具备幂等性、失败重试及异常告警能力。

### 5.2 安全与合规

- 采用账号认证、基于角色的权限控制与最小权限原则。
- 手机号、地址等个人信息按权限脱敏展示；导出和查看敏感数据需审计。
- 密码安全存储，登录支持验证码、登录失败限制和可选的双因素认证。
- 日志、备份和数据保留周期应满足适用的隐私与财务合规要求。

### 5.3 易用性

- 列表页保持统一的筛选、批量操作、导出和状态展示规范。
- 重要操作提供二次确认、结果反馈和可追溯记录。
- 支持桌面端主流浏览器，后台界面适配 1280px 及以上宽度。

## 6. 外部集成

- 支付：支付结果回调、退款申请和退款结果同步。
- 物流：电子面单、运费查询、轨迹订阅和签收状态回传。
- 前台商城：商品、价格、库存、营销活动和订单数据同步。
- ERP/WMS：库存、采购、出入库、发货与盘点数据同步。
- 消息服务：短信、邮件、站内信、企业 IM 及异常告警。

## 8. 分期建议与验收要点

### MVP（第一期）

- 账号与权限、商品、订单、库存、发货、售后、基础报表和操作日志。
- 验收：可完成“商品上架 → 下单支付 → 锁库 → 发货 → 完成/售后退款”的完整闭环。

### 第二期

- 营销活动、会员分层、财务对账、多仓与更完整的数据分析。
- 验收：可配置营销规则，准确归集优惠成本并输出经营报表。

### 后续迭代

- 多店铺、多渠道、供应商协同、智能补货、自动化客服与预测分析。

## 9. 待确认事项

- 业务模式：自营、平台招商、O2O 或混合模式。
- 订单来源与前台渠道：自建商城、抖音/淘宝/小红书等第三方渠道。
- 支付、物流、ERP/WMS、CRM 等既有系统及接口能力。
- 商品规模、日均订单量、仓库数量及高峰并发目标。
- 审批链路、退款规则、发票规则和数据合规要求。
