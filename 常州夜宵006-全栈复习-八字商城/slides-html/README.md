# 第 6 课开场复习：一笔订单的旅程

这是一个 15–20 分钟的互动复习页，用“购买八字事业详批”的场景，帮助学员重新理解用户、前端、后端和数据库的分工。

## 时间安排

1. 0–5 分钟：5 个情境问题。
2. 5–9 分钟：梳理四个角色。
3. 9–16 分钟：跑完一笔订单的整体路线。
4. 16–18 分钟：用四句话收口。

## 5 个开场问题

1. 点击“立即测算”后，谁最先接到操作？
2. 必填的出生时间没填，谁可以先提醒？
3. 有人把 99 元改成 0.01 元，谁应该最终把关？
4. 第二天订单仍然存在，它长期保存在哪里？
5. 前端能否直接连接数据库写入订单？

## 四个角色

- 用户：发出意图。
- 前端：收集操作、发出请求、显示结果。
- 后端：验证数据、执行规则、读写数据库。
- 数据库：长期保存和查询记录。

API 是前端与后端之间约定好的传话方式，不需要在这次复习中单独扮演第五个业务角色。

## 使用

直接双击 `index.html` 即可演示，不依赖网络或外部素材。

- 点击“下一步”：顺序显示下一个问题、角色或路线步骤。
- `←` / `→` 或 `PageUp` / `PageDown`：前后切换。
- 空格键：下一步。
- `F`：全屏。
- `R`：从头开始。
- 手机和平板：左右滑动。

## 讲师建议

- 每个提问出现后，先让学员回答，不立即公布答案。
- 四个角色可分配给四位学员，让每人复述自己的职责。
- 订单路线每前进一步，先追问“下一站是谁”和“传什么数据”。
- 总结时让学员用自己的话说明，不要只背名词。
