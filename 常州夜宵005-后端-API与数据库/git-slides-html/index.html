Git × AI

给代码一台“时光机”

C1 C2 C3 AI ✓ main feature/ai

AI 是动力，Git 是刹车。

方向键翻页 · F 全屏 · O 目录 · N 讲师备注 · R 重播动画

建议用时 3 分钟。先讲现场：“我让 AI 把登录页做得高级一点，它一口气改了 12 个文件，页面高级了，登录按钮也不认识我了。”提问：怎样知道它改了什么？怎样回到修改前？
01 · 先分清两件事

Git 是本地时光机，
GitHub 是云端协作站

YOUR COMPUTER Git 本地仓库

没网络也能看历史、建分支、做 Commit

push
pull
REMOTE SERVER GitHub 远程仓库
origin

让团队看到、讨论、审核和合并改动

Git ≠ GitHub。Git 也可以连接 GitLab、Gitee 或公司自建服务器。

建议用时 5 分钟。先问学员：断网之后 Git 还能不能 Commit？答案是可以，因为 Commit 保存在本地仓库。GitHub 是托管远程 Git 仓库并提供协作功能的平台。 [Sources] - https://docs.github.com/en/repositories/creating-and-managing-repositories/about-repositories - https://docs.github.com/en/get-started/git-basics/about-remote-repositories
02 · 先看整张地图

一次改动，
要经过四个位置

01工作区正在改文件
git add
02暂存区选中本次改动
git commit
03本地仓库新增存档节点
git push
04远程仓库在线分支同步
status 我在哪里？ diff 我改了什么？ log 我存过什么？
建议用时 5 分钟。这页是全课地图，不要在此处深挖命令参数。用厨房比喻：工作区是操作台，暂存区是打包台，本地仓库是自家档案室，远程仓库是云端总仓库。 [Sources] - https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository
03 · COMMIT

Commit 给本地时间线，
增加一个存档点

WORKING TREEREADME.md · login.js有改动，尚未选择
STAGING AREA等待 git add准备本次存档内容
C1初始页面09:00
C2增加按钮09:20
C3修复登录刚刚
先点 git add，把这次要保存的改动放进暂存区。

拍了照，不等于已经发朋友圈。

建议用时 6 分钟。强调 Commit 节点表示项目在那一刻的存档，不是“上传了一个文件”。演示顺序：git status → git diff → git add README.md → git diff --staged → git commit。 [Sources] - https://git-scm.com/docs/git-commit - https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository
04 · PUSH

Push 把本地新节点，
同步到在线分支

LOCAL · feature/login
C1C2C3 本地已到 C3
git push●
GITHUB · origin/feature/login
C1C2C3 Push 后同样到 C3
PUSH 前本地 C3 · 在线 C2→PUSH 后本地 C3 · 在线 C3
建议用时 6 分钟。先让学员指出 Push 前两条线的差别，再重播动画。第一次推送新分支可演示 git push -u origin feature/login，已经设置上游分支后通常可以直接 git push。 [Sources] - https://docs.github.com/en/get-started/git-basics/about-remote-repositories - https://git-scm.com/docs/git-push
05 · BRANCH

Branch 从当前 Commit，
拉出一条新时间线

C1 C2 C3 F1 F2 main · 修改文案 feature-login · AI 试验 从当前 C3 分叉 feature-login（未切换）
先创建分支指针；这一步不会切换，也不会产生新 Commit。

不是复制一份“项目-副本”，而是在同一棵历史树上拉出新线。

建议用时 7 分钟。严格按三步演示：git branch feature-login 只在当前 C3 创建分支指针；git switch feature-login 才切换 HEAD；后续 Commit 才让新时间线长出 F1、F2。用“平行宇宙”比喻：AI 在 feature-login 尝试新登录页，main 可以继续修文案。本页只讲分叉，Merge 和冲突留到后续。 [Sources] - https://git-scm.com/book/en/v2/Git-Branching-Branches-in-a-Nutshell - https://git-scm.com/book/en/v2/Git-Branching-Basic-Branching-and-Merging
06 · COMMAND MAP

不用背大全，
先会看、会存、会分、会同步

01 · 看 git status我在哪里？ git diff我改了什么？ git log --oneline过去存了什么？
02 · 存 git add <file>选中本次改动 git commit -m "..."建立本地存档
03 · 分 git branch查看本地分支 git switch -c <name>建立试验分支
04 · 同步 git clone <url>下载完整仓库 git pull取回并尝试合并 git push上传本地 Commit

迷路时先跑 git status，不要立刻猛踩油门。

建议用时 6 分钟。这页不要逐条讲参数，让学员先记四个动词：看、存、分、同步。fetch 可在口头上补充为“只取回远程信息，不直接合并”，但不列入小白第一天必背命令。 [Sources] - https://git-scm.com/cheat-sheet.pdf
07 · WORKTREE · 知道即可

同一个仓库，
可以摆出两张工作台

project/ 你的工作台 main 分支
SHARED同一个
Git 仓库
project-ai/ AI 的工作台 feature/ai-tests 分支
Branch 是不同时间线 · Worktree 是不同文件夹
git worktree list小白先会查看就足够
建议用时 3 分钟。只讲概念：你可以在 project/ 继续修主线，AI 在 project-ai/ 写测试，两个目录共享同一仓库历史。不在这节课演示删除、修复、锁定或强制操作。 [Sources] - https://git-scm.com/docs/git-worktree
08 · SAFE AI WORKFLOW

AI 负责加速，
人负责看路

01git status确认现场
→
02git switch -c开试验分支
→
03AI 修改明确边界
→
04git diff检查结果
→
05git commit / push审查后发布

“只检查 Git 状态，不要修改。”

“先创建独立分支，不要直接改 main。”

“总结当前 diff，按文件说明改动和风险。”

“推送前检查状态和测试，不要强制 push。”

建议用时 6 分钟。强调“先看后改”：当 AI 建议 reset --hard、clean -fd 或 push --force 时，先问它会影响哪些文件、能否恢复、是否有更安全的方案。不把危险命令放进小白的主命令卡。
09 · 课堂挑战

AI 要修改 README，
你的第一步是什么？

选一个答案，看看你是不是已经会“先看路”。
Commit本地存档 Push上传同步 Branch新时间线 Worktree独立工作台
建议用时 5‑8 分钟。先让学员投票，再点击揭晓。正确路线是：git status → 确认分支 → 必要时新建分支 → 让 AI 只改指定范围 → git diff → 测试 → commit → push。结尾不说“谢谢”，让学员用四句话复述本课。
