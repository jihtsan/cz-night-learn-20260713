PART A · WEB HISTORY

Web 最初要解决的，
是“怎样分享文档”

它像一个全球共享的资料柜，还不像今天的应用。

建议用时 3 分钟。Tim Berners-Lee 1989 年在 CERN 提出 Web，目标是满足科研机构之间自动化信息共享的需求。第一个网站也是对 Web 项目本身的说明。来源：https://home.cern/science/computing/the-birth-of-the-web/
02 · 静态 WEB

服务器像仓库管理员：
你要哪份，它就拿哪份

浏览器请给我 /about.html
HTTP
Web 服务器index.htmlabout.htmlcontact.html
每个人看到的几乎都一样
建议用时 3 分钟。强调“静态”不是指没有动画，而是服务器交付的内容事先已经写好。即使 CSS 有动画，页面也可以是静态站点。

同一个网址，开始因人、因时、因数据而不同。

建议用时 4 分钟。口述例子：新闻首页自动显示最新文章；论坛显示刚发布的帖子；用户登录后看到自己的订单。这是“后端”第一次作为故事主角出现。

数据库让网站有了“记忆”

注意数据库早于 Web 出现；动态网站只是把它带进了日常网页。
建议用时 3 分钟。不要说“因为网站才发明数据库”。更准确的表达是：当网站需要注册、发帖、购物和订单时，后端程序与数据库成为动态网站的关键部分。
05 · AJAX

点一次按钮，
不必再换一整张页面

BEFORE整页重新加载
购物车 +1 → 白屏 → 整页回来
AFTER只交换必要数据
购物车数字局部更新

网页开始像桌面软件：更流畅，也更依赖 JavaScript 与后端通信。

建议用时 3 分钟。不需讲 XMLHttpRequest 的详细语法。举邮箱、地图、聊天的例子：每次操作都整页刷新，体验会很差。可补充阅读：https://developer.mozilla.org/docs/Glossary/AJAX

07 · 历史不是年份表

每当网页想多做一件事，

技术不是从名词开始的；技术是从“现在还做不到什么”开始的。

建议用时 2 分钟。这一页用来回收历史线，不要重复前面所有内容。可让学生用一句话回答：数据库补了什么？API 又补了什么？

建议用时 2 分钟。避免让学生觉得上节课白学了。纯前端适合作品展示、个人工具、离线小应用和原型；业务一旦需要共享状态与权限，就需要突破浏览器边界。

09 · 职责边界

前端表达“我想做什么”，
后端决定“能不能做”

FRONTEND看得见、点得动展示商品收集表单发起请求显示结果
意图信任边界结果
BACKEND验证、计算、执行身份与权限参数校验业务规则数据库操作
建议用时 4 分钟。举例：前端可以先检查库存是否为空，让用户更快获得提示；但后端仍然必须再检查一次，因为前端请求可被修改或伪造。

建议用时 5 分钟。点击“拨打 API”演示。后端的脚本是相对固定的：检查、查数据库、保存、返回。每次通话中的商品数据可以不同。强调 API 不只是一个 URL，而是一套沟通合同。

12 · 不要相信前端

用户把¥299改成¥1，
后端会照单全收吗？

浏览器发来的价格
→后端重新查价
数据库中的真实价格¥299等待验证

前端表示用户的意图；最终价格、权限和库存必须由后端核实。

建议用时 5 分钟。先让学生在输入框改价格，再提交。这个演示用来解释为什么前端校验只是提升体验，不是安全边界。“有后端”也不代表自动安全，仍需要身份、权限和参数验证。
13 · DATABASE

数据库不只是“存下来”，
还要让数据可查、可改、可关联

idnamepricestockstatus

建议用时 4 分钟。本节不深入 SQL，也不讲范式。小白先理解表、行、列和 ID。可口述补充：普通文件也能保存，数据库的价值在于结构化查询、并发访问、关系和一致性管理。

18 · 优势与代价

如果把后端当成不同类型的交通工具

Node.js同语言的换乘线

前后端都用 JavaScript，上手快；重计算需要另做安排。

Python容易驾驶的 AI 接驳车

语法直观、AI 生态强；不以极致运行性能见长。

Java企业级标准生产线

JVM 带来跨平台能力，生态成熟；概念多、通常更重。

PHP为网站而生的老牌工具箱

入门与部署简单；大项目更依赖清晰规范。

Go轻量高效的货车

性能、并发与部署体验好；复杂业务可能写得更明确也更多。

C#微软企业生态快车

工具与工程化完整；需要进入 .NET 的整套生态。

建议用时 6 分钟。需要口述三个纠偏：一，Java 是“一次编译，在有合适 JVM 的环境运行”，不是完全无需适配；二，PHP 可以嵌入 HTML 在服务器生成页面，但 PHP 本身通常不在浏览器运行；三，Go 的优势来自编译、相对轻量的运行时与并发模型，不是“只有 Go 才会自动内存管理”。

20 · 快速判断

这件事，应该放在前端、
后端，还是数据库？

建议用时 4–7 分钟，用于扩展到 75 分钟。先让学生投票，再点击揭晓。库存的“保存”在数据库，但“扣减库存的规则”在后端；用这个追问说明三者是协作，不是相互排斥。
